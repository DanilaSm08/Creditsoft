# Тестирование — ЛР7

Среда: Python 3.12, pytest, pytest-django, Django TestCase, pytest-cov, pytest-html, Playwright/Chromium. В локальном быстром прогоне применяется изолированная SQLite; интеграционный прогон повторён с PostgreSQL 16. Рабочая БД не очищается: pytest создаёт отдельную `test_creditsoft`.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe tools/check.py --stage regression --e2e
```

Для PostgreSQL после `docker compose up -d`:

```powershell
$env:POSTGRES_HOST = '127.0.0.1'
$env:POSTGRES_PORT = '55432'
$env:POSTGRES_PASSWORD_FILE = (Resolve-Path .local/postgres_password).Path
.\.venv\Scripts\python.exe tools/check.py --stage postgres-regression --e2e
```

`tools/smoke.py` проверяет реально развёрнутый стек по HTTP: создаёт пользователя demo при первом запуске, сохраняет анкету, получает 900 баллов и четыре предложения, проверяет загрузку логотипов, повторное открытие и выход. Пароль сохраняется только в `.local/demo_credentials.json`.

## Наборы проверок

| Набор | Что доказывает |
|---|---|
| test_accounts.py | Регистрация, проверка пароля и дубликата, хеш, сессия, выход, CSRF, запрет внешнего redirect |
| test_questionnaire.py | Все поля, нулевые/отрицательные/нечисловые значения, границы суммы и срока, возраст и стаж, запись и редактирование, изоляция владельца, ограничения БД |
| test_scoring.py | Формула нагрузки, все пороги трёх таблиц рейтинга, минимальный/максимальный балл, повторяемость и неверные входы |
| test_results.py | Каталог и его повторная инициализация, каждый фильтр, равные ставки, отсутствие предложений, снимки, повторная оценка, доступ владельца |
| test_browser.py | Два пользовательских сценария: регистрация/анкета/ошибки/выход и оценка/карточки/редактирование/повторный расчёт; ширины 1440 и 390 px |
| test_health.py | Доступность приложения и соединения с БД, допустимый HTTP-метод |

Автоматически собираемая карта `artifacts/runs/<stage>/test-map.json` связывает отдельные тесты с CR-01.1–CR-08.3. Все 24 функциональные задачи представлены. PR-01 проверяется браузером. INF-01 — health, миграциями и прогоном PostgreSQL. QA-01 — настоящим документом, картой покрытия требований и её проверкой при сборе релизных свидетельств. QA-02 — полным регрессионным прогоном. RL-01 — Compose и health всех трёх контейнеров. RL-02 — сборкой wheel/sdist, выпуском в GitHub Releases и smoke после развёртывания. Я связал организационные задачи с артефактами выполнения.

## Отчёты и критерии приёмки

На каждый запуск создаются `tests.html`, `junit.xml`, `coverage/index.html`, `coverage.xml`, `coverage.json`, `test-map.json`, `lint.json`, `metrics.json`, журналы и снимки браузера. При падении браузерного сценария сохраняются trace и скриншот. Пакет wheel/sdist строится только после успешного стиля, проверки миграций и тестов. Минимальное совокупное покрытие строк/ветвей — 85%..

Из покрытия исключены автоматически сгенерированные миграции и команды управления; в него не входят HTML/CSS/JS. Поведение интерфейса дополнительно проверяет Chromium; каталог — идемпотентный seed и тесты отбора.

Ветка `ci/protection-probe` содержит намеренно падающий тест исключительно для доказательства защиты main. Она не включается в продукт и закрывается без слияния. Такой запуск учитывается отдельно от случайных дефектов при анализе успешности CI.
