# Соответствие архитектуре ЛР4

CreditSoft реализован как модульное Django-приложение `core`. Отдельные файлы представляют логические компоненты диаграммы, а не независимые сетевые сервисы. Вспомогательные библиотеки входят в один процесс приложения. Нумерация вызовов ниже относится к сценарию, поскольку диаграмма компонентов сама по себе порядок выполнения не задаёт.

| Компонент | Назначение в реализации |
|---|---|
| accounts.py, Django Auth | Регистрация, хеширование пароля, вход, сессия, выход |
| questionnaire.py | Приём запроса анкеты, валидация обеих форм, сохранение и возврат страницы |
| validation.py | Правила ФИО, паспортных реквизитов и допустимого возраста |
| forms.py | Типизация ввода, проверка чисел и стажа, привязка ошибок к полям |
| scoring.py | Чистая функция нагрузки и рейтинга, версия правил edu-1.0 |
| offers.py | Отбор активных продуктов и сортировка; создание снимка каталога |
| results.py | Запуск расчёта и отображение результата, ограничение доступа владельцем |
| repository.py / ORM | Загрузка и атомарное сохранение анкеты; блокировка пользователя при записи |
| models.py | BorrowerProfile, FinancialData, LoanOffer, Assessment; ограничения и индексы БД |
| views.py | Проверка доступности приложения и соединения с базой /health/ |
| urls.py | Сопоставление URL обработчикам |
| templates | Серверные HTML-страницы, поля ошибок, карточки предложений |
| static / Bootstrap / CSS | Адаптивная сетка, оформление, четыре логотипа учебного каталога |
| JavaScript | Перевод фокуса на первое ошибочное поле; расчёты от JavaScript не зависят |
| PostgreSQL / psycopg | Постоянное хранение данных и драйвер соединения Django |
| pytest / Django TestCase / Playwright | Автоматические проверки логики, интеграции и браузерных сценариев |
| Ruff / coverage.py / Radon / build | Стиль, покрытие, сложность, сборка Python-пакета |

Последовательность сохранения: браузер → Nginx → Gunicorn → Django middleware (сессия, CSRF) → questionnaire → ProfileForm + FinanceForm → validation и ограничения моделей → repository → ORM → PostgreSQL. Обе формы проверяются независимо, а сохраняются вместе; если есть ошибка, запись не выполняется. Ответ возвращается через шаблон с сообщениями возле полей.

Последовательность оценки: POST /assess/ → middleware и проверка входа → results.evaluate → блокировка строки пользователя и загрузка сохранённой анкеты → scoring.calculate → offers.select_offers → ORM/PostgreSQL → сохранение Assessment со снимками → перенаправление на GET /results/<id>/ → шаблон результата. Повторное открытие результата читает снимок, а не пересчитывает его. Чужой идентификатор возвращает 404.

| Узел развёртывания | Назначение и размещение |
|---|---|
| Рабочая станция / браузер | Отображает HTML, отправляет формы и хранит cookie сессии |
| Docker Desktop / Compose | Локальная среда запуска контейнеров и сетей |
| Nginx | Порт 8080 на 127.0.0.1, статические файлы и проксирование запросов |
| Gunicorn | Два рабочих процесса WSGI, внутренний порт 8000 |
| Python / Django / CreditSoft | Прикладная логика, формы, сессии, ORM, шаблоны |
| PostgreSQL 16 | Таблицы пользователей, анкет, каталога, оценок и сессий |
| Том database | Данные PostgreSQL, сохраняющиеся при пересоздании контейнеров |
| Том static | Статика после collectstatic, доступ Nginx только для чтения |
| Compose secrets | Локальные файлы ключа Django и пароля PostgreSQL, исключённые из Git |
| Gitea | Отдельный сервер репозитория, задач, PR, тегов и выпусков, порт 3030 |
| act_runner и контейнеры CI | Запуск проверок на push и pull_request, хранение артефактов в Gitea |

Локальные соединения: браузер → Nginx по HTTP на loopback; Nginx → Gunicorn по HTTP во внутренней сети Docker; Django → PostgreSQL по протоколу PostgreSQL через psycopg. Порт 55432 доступен только на loopback для интеграционных тестов с Windows. Публичное развёртывание и TLS не выполнялись. HTTPS и защищённые cookie включаются при развёртывании за TLS-прокси через DJANGO_HTTPS=1. SQLite используется только как запасная среда разработки и быстрых тестов.
